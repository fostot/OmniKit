# OmniKit feature scope

This tracks the requested product, including unfinished work. Source implementation,
a successful build, installation, and observed in-game behavior are separate states.
Items marked implemented still require the integration and live checks described
in the release notes before they can be called verified in game.

| Requested capability | Current state |
| --- | --- |
| Local companion sayings library | Companion → Sayings offers 418 original lines: 80 Universal and 26 for each of thirteen companions, across eight activity contexts. Search, scope/context filters, add/edit, enable/disable, soft removal/restore, interval and explicit preview/merge JSON controls are implemented. SQLite preserves edits and disabled/removed seed lines across reloads; settings JSON remains separate. Bubbles choose eligible universal and current-companion lines, avoid recent repeats and make no AI calls. Synthetic persistence/controller and offscreen UI checks are separate from live game validation. See [Sayings](SAYINGS.md). |
| Hotkey launcher with natural synonyms such as guild, community and free company | Search/catalogue and launcher UI implemented. Width, height, text size, visible result count, horizontal position and top position are adjustable; reset restores the compact defaults. Additional results remain reachable by scrolling/arrow keys. Game validation pending. |
| Open game panels and installed plugins | Catalogue reads the game's main commands and Dalamud's exposed plugin UIs; live behavior pending. |
| Find community recruitment | Official Community Finder links open in OmniKit's in-game browser. Live rendering inside FFXIV remains unverified. |
| Aetheryte and aethernet-shard unlock checklist | Game tools → Unlocks → Aetheryte reads named destinations and native attunement flags, with Current zone, All areas, per-zone tabs and a searchable picker. Physical major/shard ticks come only from observed game flags; virtual exits have no attunement box. Explicit scoped Start uses vnavmesh ground paths, closest current-zone targets, finite one-interaction legs and 10 verified unconditional walking transitions. Boats, conditional crossings and a complete world tour are not implemented. Stop/Esc/command cancel; unsafe states, ownership loss and failed/gated travel cannot silently mark completion. All movement/native attunement remains unverified in game. See [coverage and controls](UNLOCKS.md). |
| Camera-directed interaction | Eight world-object categories can be toggled independently. Horizontal aim tolerates vertical camera pitch while a candidate center remains visible. A fresh press selects and confirms targetable objects before interacting; looking alone never changes the hard target. Separate hostile/neutral enemy switches start off; enemy actions require an explicit choice of Target only or Target + start auto-attack. Only a fresh key press acts. Enemy classification uses the game's current hostility flag and can change. Live enemy behavior requires validation. |
| Independent visible-target HUD and configurable key | Styled text without a frame; no candidate means no gameplay text. Active NPC/object interactions and cutscenes hide it. Paused actions hide the normal HUD while detection continues; only explicit HUD editing shows a paused sample. Passive player bags remain actionable unless text input or another blocking state is active. Font size, optional outline and 11 text-effect choices are in HUD, with intensity, animation and speed controls. Outline thickness accepts 0.5–4, default 1, and follows the primary effect glyphs. Modify opens these controls with an explicit editing sample. Shift-right-click opens Lock/Unlock, Move, Modify and Hide. Full Ctrl/Alt/Shift chords are recorded by pressing keys. Live behavior still needs verification. |
| Gathering gearset switching and restoring prior equipment | Gathering service implemented; saved opt-in, restoration preference and miner/botanist choices are in the settings schema. Behavior requires live verification. |
| Character window job switcher with missing-set recovery | Off by default in Launcher. Independently replaces the corresponding Simple Tweaks/HaselTweaks tweak. Never creates another current-class set when one already exists. Creates a current snapshot only when that class has no set. Missing targets follow weapon/crystal, create set, native Recommended Gear, then reassignment of that same new row with verified class naming; existing targets are equipped directly. Preflight, observed completion, interference checks and bounded failure restoration are implemented. Existing sets are never overwritten. Native clicks/equipment changes still require live acceptance. See [scope and sources](JOB-SWITCHER.md). |
| NomNom food automation | Automations → NomNom, off by default with Automatic selected. Detects supported food in personal bags and lists NQ/HQ quantities. With Keep +EXP buff active enabled, requests eligible food only after Well Fed expires. Automatic ranks EXP bonus, then item level, then quality preference, skipping unusable food; a manual selection remains exact with quality fallback. Turning either toggle off pauses consumption. Native usability and busy-state checks, observed completion and bounded failure handling precede further attempts. No AI calls or persisted inventory snapshots. Native consumption remains unverified in game. |
| Verified quest-item use | Off by default. Two mapped cases: Tiller's Shovel on cumbersome rocks in Rocks in a Hard Place, and Fetid Dodo Flesh on suspicious mounds in Forbidden Island. Quest/tracker/inventory/confirmed-target/native-usability guards precede one item request per press. Debris stays ordinary interaction. Generic quest solving and third-party adapters are not implemented; native game execution remains unverified. |
| Verified quest-emote use | Off by default. The first mapped case uses `/soothe` on the irate coachmen in A Bridge Too Full. A fresh press confirms the target before one emote request; a blocked matched rule never falls back to talking. Native game execution remains unverified. See [scope and sources](QUEST-EMOTES.md). |
| Next Action icon | Only a matched quest item or emote for the current candidate supplies the preview and blocked reason. Ordinary interactions and enemies never show this extra button, even unlocked. Locked mode shows one icon; unlocked mode adds the NEXT ACTION heading and drag area. Its separate lock control does not execute an action. Clicking submits one guarded request; observation alone never acts. Live behavior pending. |
| Manual quest item bar | The Quest Items tab controls a paged bar with up to eight visible items. It reads usable non-ground KeyItems and ordinary bag items explicitly tracked for an accepted quest's current sequence. It excludes arbitrary potion inventory. A manual click rechecks the existing target, exact stack and native usability, with no auto-target, queue, retry or claim that the item belongs to that target. Full item tooltips wrap without a scrolling child. Snapshot data is not persisted, logged or sent to AI. See [item coverage](QUEST-ITEMS.md). |
| Native Umbra plugin-menu entry | Standard main/config UI hooks are the integration contract; enabled by the main plugin wiring. |
| Native Umbra toolbar widget and popup with matching icons | Optional sidecar implemented using actual Umbra widgets, menus and Font Awesome icons. Add its DLL through Umbra's own plugin interface; it does not silently edit a toolbar. |
| Thirteen whole-body companions | Moonblob is the default, joined by Wink, Nova, Mochi, Puff, Orbit, Ember, Prism, Nib, Echo, Fizz, Glim and Rune. The five additions are an ink drop, ghost, soap bubble, star and rune stone, with their own shapes, faces and signature magic. Each uses one complete limbless body; The default Moonblob rolls; rigid alternate bodies stay upright while soft variants can roll. The other companions float from stable images. Atlas artwork supplies blink, mouth and reaction states. Four additional everyday looks per original companion add 32 choices, with Random and a separate optional look timer. Ember curls/flickers, Mochi squashes and Puff billows continuously; Orbit has a ringless core with layered rotating/tilting rings and separate movement/speed controls. Nib ripples with a delayed tip, Echo has a travelling curl, Fizz has a bubble wobble, Glim flexes, Rune rocks with weight, and Wink/Nova/Prism have distinct soft motion. Painted hats reserve deformation space, so tall crops do not cancel motion. Eyes and bows share the body warp. Orbit's body/hat and both facing-aware ring passes share one gentle rigid travel sway and actual pose center. Six aura palettes remain available. Wink is the plugin icon. Artwork and geometry checks are separate from live game appearance. |
| Holiday bodies, fitted accessories and optional rotation | Nine painted body themes for each of the eight companions plus optional fitted accessories cover All Saints' Wake, Starlight, Heavensturn, Valentione, Little Ladies' Day, Hatching-tide, Make It Rain, Moonfire Faire and The Rising. Auto reads supported native festivals; unknown/conflicting states do not guess by month. Only explicit official date windows may substitute when native data is unavailable. Manual selection remains available. Optional local rotation chooses another companion every 30–3600 seconds, retaining the saved manual choice. All 72 holiday looks have eight complete poses. Body, accessory and holiday-home switches are independent; automatic identity changes defer during pickup/nap/hover; manual selections update immediately, including in bed. Together with the eight originals and 32 everyday choices, there are 112 body looks. Orbit's rings follow the active holiday body with nine palettes and ring-plane motifs, preserving the original movement; Magic hides the extra motifs. |
| Pick up the companion and interact with supported frames | Optional Frame interaction under Companion → Appearance. Read-only surface snapshots cover visible rectangular native addons and compatible windows/bars in the same ImGui context, including compatible NoMouseInputs windows. Full-screen canvases are not universally supported. Walking off a supported thin HUD strip falls toward a lower frame or the screen floor before returning to the roaming area. Grounded roaming uses flat supports, bounded hops and open-edge falls instead of free-space walking; unreachable routes stop at their actual reached position. Repeated failed hop/fall excursions back off, then quarantine that route after three failures. Meaningful supported progress, changed geometry/destination, resizing or pickup can release it; small observation jitter and wandering waypoints cannot. The optional pickup hand centers the companion/house beneath its grip and has an independent 8–192 px size, default 38.4. Native game surfaces still need live validation. |
| Independent companion house and naps | Dragging the house changes only its own screen position. There are 13 homes including Default, three everyday styles and nine holiday designs, plus Random; five hand designs also support Random. Normal roaming stays in the drawn area and routes around the house; nap trips can leave it at about twice normal speed, shrink in front of the visible doorstep, cross the measured doorway before wall masking, settle, sleep, wake and return continuously. Default uses a measured curved arch; all thirteen homes retain mirrored opening geometry. They stay small through the doorway, step outward, then grow in front of the house. Accessories hide on entry and return outside only when enabled. All thirteen companions have inspected entrance/sleep artwork. Painted costumes switch to their matching bare body on entry and restore the hat outside. Defaults are about 45 seconds awake and 20 asleep, adjustable to 15–300 and 5–120 seconds. Naps and chimney sleep symbols have separate switches. Pause freezes a trip; disabling naps, hiding or moving the house returns without teleporting. Source-linked state checks and offscreen rendering are separate from live appearance. |
| Companion comments and blinking | Home visibility, grab hand, local text comments and all-companion blinking have separate controls. Comment interval is 30–600 seconds; blink interval is 1–10 seconds and also requires animation enabled. Idle and walking blinks change only eye regions; fitting mode freezes the body while its independent eye preview can blink. An optional Fourier-smoothed blink affects Wink only. Comments do not use AI, the microphone or synthesized speech. |
| Accessory fitting stage | A still, centered companion preview supports accessory drag, corner/slider resize, head-relative rotation and explicit Save fits. Only the five complete bows remain editable overlays. All four hats are painted into complete costume bodies; no cutout hats or rear hat pieces are drawn. Fits are keyed by companion/body/accessory in local head-width units with an angle in degrees and persisted through the existing bounded JSON/SQLite DTO. Multiple drafts survive selector changes; Cancel keeps saved fits, Reset is not persisted until Save, and failed saves roll back. The real companion pauses its state/clocks. |
| Painted hat costumes | All thirteen companions have witch, Starlight cap, top hat and straw hat costumes, each painted as one complete body across eight poses. Paintings preserve the complete visible brim. Painted costume chooses None, Auto or a named theme. Manual changes apply immediately; Auto follows the supported active festival. Original body choices remain saved. The atomic wardrobe pack holds 65 pose sets including thirteen bare bedtime bodies, 520 frames and 125 measured eyes. Body-based scale and reserved visual padding keep tall hats from shrinking the body. |
| Explicit mouth-animation preview | Implemented through Preview animation. Synthesized speech and audio-driven lip sync are not implemented. |
| Material-aware body motion | All 32 everyday and 72 holiday bodies have exact artwork-ID profiles, with distinct gel, cream, water, bubble, cloud, wisp, flame, silk and rigid materials. The 52 costumes retain species motion with small timing changes. Bounded local start/stop/turn responses follow actual travel; strength and reactions are configurable. One connected mesh carries eyes and bows together, and Orbit retains one rigid body/hat/ring transform. No model training or inference runs in the game. |
| Scene sizing | Companion, home and hand sizes are independent. A 0.5–2 scene multiplier scales them together without replacing those values; each size group has its own reset. Doorway scale adapts to the home opening. The roaming area stays where the user drew it. |
| Rear-facing bedtime poses | Seventeen optional atlases supply four whole-body turning/climbing poses for 117 base/everyday/holiday identities. Costume entry uses the matching bare identity. The sequence shrinks at the doorstep, turns through a narrow pose, climbs into the opening and settles with a small wiggle. Exact look matching prevents a different material appearing at the door. Textures load on request; no separate limbs or overlapping body crossfade are used. |
| Minimal launcher and organized settings | Idle launcher remains input and gear. Settings use four tree folders, a wide resizable sidebar or compact navigation drawer, and focused tabs inside each pane. Routine views show few controls; advanced settings and explanations expand on request. Companion tabs and tree shortcuts stay synchronized. Exact labels are NomNom and Soft Interact HUD. Minimum480×330 and scales1/1.5/2 have offscreen checks; live game appearance remains separate. |
| Turn off avatar, animation, magic accents, frame interaction, voice and AI independently | Configuration, interface controls and local storage implemented. Frame pickup, perching, containment and falling have separate switches. |
| Voice requests and configurable phrases bound to launcher actions | Local Windows one-phrase recognition, UI, voice bindings and storage implemented; recognition quality and action dispatch require live checks. Microphone capture is explicit and time-limited. |
| Optional AI-provider text chat | Explicit API, ChatGPT, Codex CLI and Claude CLI choices. Each accepted Ask permits at most one inference request; concurrent submissions are rejected, with no queue, automatic retry or provider/model fallback. Fixed XIV/selected-companion instructions, bounded replies and no executable game actions. CLI generation is paused; API/ChatGPT chat remains available. Provider connection tests are distinct from real account sign-in and inference. See AI-CONNECTIONS.md. |
| Use the tool fully without AI | Core launcher and interaction do not need an AI connection. First-run selection is recorded locally. |
| Sign in with ChatGPT using OAuth | OmniKit's own public-client registration, browser consent, PKCE/state/nonce, signed-token verification, separate DPAPI account storage, serialized rotating refresh and bounded streaming. Real sign-in and plan inference require user acceptance. |
| Codex/Claude CLI integration | Generation is paused because the CLI cannot establish OmniKit's strict one-Ask/one-inference limit. CLI availability/probe and supported sign-in flows remain available through the CLI's own login. No token copying or generic web-session bridge. |
| Claude sign-in | Delegated to Claude CLI's own supported browser login. There is no separate generic Claude web-session or cookie bridge. |
| Keep the character and topic focused; resist instruction override | AI instructions implemented, with hard action limits in code. Perfect resistance to prompt injection is not promised. |
| Reuse other plugins' data and actions | Versioned OmniKit action-registration IPC implemented. Providers must explicitly integrate; arbitrary private plugin files are not read. Read-only AI knowledge adapters remain planned. |
| In-game browser | Wiki and web actions use an out-of-process WebView2 child window with a dedicated profile. A menu icon reveals controls; the close X stays visible. Close/hide stops the helper and engine, with no prewarm. Per-session protection defaults on and blocks script popups and a limited original list of 60 known ad/tracking hosts, not all advertising. Controls offer a session protection switch and unpacked-extension management. Native-UI hover cutouts mitigate overlap; actual FFXIV flicker, focus, DPI and fullscreen behavior remain unverified. Windowed/borderless mode is intended. No Browsingway dependency or silent external-browser fallback. |
| Optional capture of other game-process web links | Off by default, including migrations. Standard HTTP(S) ShellExecute calls from the same game process can start the browser on demand; merely enabling capture does not prewarm it. Authentication links, non-web schemes, custom process launches and other processes are excluded. This does not intercept every way a plugin can launch a browser. Live behavior requires validation. |
| Local database for settings | SQLite schema v14 atomically migrates v1–v13, preserving preferences, keyboard chords, local AI consent and prior rendered home/hand sizes with explicit validation. New automation and Character-window switching remain off on migration. Legacy house coordinates derive from the previous roaming box. All migrated wiki/web navigation uses the in-game browser. Conversation/audio storage is not enabled. |
| JSON settings export/import | Implemented through an explicit whitelist. Entire imports validate before changes; credentials and callbacks never appear in exports. Imported preferences cannot grant new AI transmission consent. |
| GitHub repository, packaged releases and custom Dalamud repository | Public fostot/OmniKit repository, immutable preview releases and repo.json feed. Public download integrity is verified at publication; successful loading in each user's game is separate. |

## Local data and imports

The earlier rabbit/bear art and rigs were retired locally and excluded from current
source files and packages. Previous published releases and history remain unchanged.
Source 17 adds head-relative accessory fitting, stronger holiday forms, immediate
manual appearance updates, universal blinking and companion poofs. Source 15
introduced everyday and painted holiday bodies, fitted accessories, home and
hand choices, grounded hopping, expressive body motion and Orbit's rings.

`omnikit.db` lives in the plugin's configuration directory. It stores settings,
selected avatar, shortcut choices, gathering preferences, AI connection preferences
and voice-to-action bindings. API keys remain in a separate endpoint-bound Windows
DPAPI credential store. ChatGPT registrations and tokens use a different protected
store, outside the settings DTO, database and exports. CLI credentials remain
under the selected CLI's control.

Exports use schema version 14 and include only explicitly listed preferences.
Versions 1–13 migrate atomically, preserving previous fields, keyboard
chords and local consent. Independent home and hand sizes derive from the previous
companion size and hand scale; scene scale starts at 1. Body-motion strength and
movement reactions have separate controls. Fits use offsets in
head-width units and uniform scale, with strict identities, bounds, uniqueness and
detached collections. Older house coordinates derive from
the old roaming box's midpoint/bottom; its later movements do not change the box.
Quest-item use and capture of other game-process web links both default off.
Existing effect IDs and appearance choices are preserved. In-game web navigation
is enabled for every migrated profile. Older plugins cannot open a version 14 database. Exports
contain no credential values, conversation history or audio. Custom provider URLs
and voice phrases can still reveal personal choices; exported files are local user
data, not repository source or release assets.

Imports reject unsupported schemas, unknown/missing/duplicate fields, invalid
types or ranges, unsafe endpoint URLs, colliding shortcuts and duplicate voice
phrases. The maximum JSON size is 256 KiB. An imported profile keeps AI enabled
only if it was already enabled locally and the endpoint and connection are unchanged; otherwise
the user must enable it explicitly in settings. The import interface always disables AI. Restoring one's own local database
retains the previous local AI choice.

HUD effects are None, Shadow, Soft glow, Gentle shimmer, Rainbow, Neon pulse,
Chromatic glitch, Hologram, Flame, Frost and Light sweep. Intensity accepts 0–2,
speed accepts 0.1–3, and effect animation can be disabled independently of the
companion. Outline thickness is 0.5–4, default 1, and follows the primary effect
glyphs. These are text styling controls, not changes to game effects.
